# Native analysis coordinator — November 3, 2026

`NativePhotoAnalysis`, an opt-in library product in the SIFTBridge package, connects
live file decoding, conservative orientation, Vision evidence, Swift measurements,
native SIFT, grouping and the accepted focus/tier policies. The production Python
CLI, its database and original photographs are unchanged. No Photos access, image
export, archiving or UI is added by this milestone.

## App entry point

```swift
import NativePhotoAnalysis

let coordinator = AnalysisCoordinator() // retain one per analysis service
let inputs = selectedURLs.map { AnalysisInput(id: $0.absoluteString, url: $0) }
let result = try await coordinator.analyze(inputs) { progress in
    // Runs off MainActor. Forward the immutable value to your UI's MainActor.
}
// result.photos: typed tiers, reasons, focus flags and rank within the displayed set
// result.orderedGroups / orderedUngrouped: display order, indexing result.photos
// result.sources: caller identity, file URL, SHA-256 and applied quarter-turn
// result.timings: optional wall-clock seconds by phase and total
// result.pairEvidence: Vision distance and native SIFT measurements for every pair
// result.batch: complete typed input evidence for policy evaluation
// result.policyJSON: full existing focus/tier output, retained without lossy summaries
```

Call from a cancellable Swift Task; cancelling that task throws `CancellationError`
at the next checkpoint. Do not detach the call from the task you intend to cancel.
The serial actor keeps Vision and non-Sendable SIFT handles confined. It has no
internal awaits, so another run on the same actor queues until the current run
finishes. Separate coordinator instances can run concurrently; the app should keep
one service instance to bound aggregate memory. Progress callbacks should be quick;
UI subscribers must hop to MainActor. No AppKit/UIKit, process execution or Python
runtime is used by the library.

Checkpoints occur during checksum reads, between display scales and analysis
operations, before every pair comparison and around policy/final verification.
Individual synchronous Vision, focus, edge, SIFT and policy calls finish before
cancellation takes effect. Progress has separate validating, analyzing, matching,
ranking, verifying and complete stages; matching notifications are throttled to
32 pairs. The API returns no partial success on failure or cancellation. There is
no on-disk job state, resume support or result cache yet.

Only one image scale's display pixels are processed at a time. The batch retains
compact measurements, Vision feature prints and reusable SIFT descriptors; these
are released before ranking. Pair records still grow quadratically. This is a
bounded decoding strategy, not a demonstrated mobile memory ceiling.

The first adapter accepts 1–500 distinct local JPEG, HEIC/HEIF, PNG or single-image
TIFF files with distinct caller IDs. Multi-image sources fail explicitly. The
Mac app's Photos picker stages selected images as temporary local files for this
API. The caller owns
security-scoped access for the entire operation. SHA-256 checks before and after
analysis reject changed sources; they do not lock files against concurrent writers
or prevent an external change immediately after final verification.

Full tier evidence requires macOS 15 / iOS 18 or newer and fails explicitly on older
systems. Package deployment targets remain macOS 14 / iOS 17 for other library
features. The device builds and runtime availability still require full-Xcode and
physical-device validation. Keep accepted production behavior until those gates
and broader integration checks pass.

## Build and run

Build OpenCV and SIFTBridge using its existing instructions, then use the resulting
binary directory:

```sh
OPENCV_ROOT=/path/to/opencv/install experiments/apple_native/SIFTBridge/build.sh
/path/to/bin/analysis-checks
/path/to/bin/native-analyze < /path/to/absolute-paths.json > /path/to/new-result.json
```

`native-analyze` defaults to conservative visual orientation; `--no-auto-rotate`
disables that additional step, retaining embedded orientation. It prints progress
to stderr and a single complete JSON result to stdout. The shell owns output
redirection; choose a new path. Production source photos are never written.
The command is a Mac validation adapter; apps link the library product directly.

## End-to-end comparison

Keep private fixtures and results outside Git, for example under sibling
`../IntegrationChecks/`. The baseline is generated by the unchanged accepted CLI
analysis code, using isolated research artifacts and no database mutations:

```sh
.venv/bin/python -B experiments/apple_native/freeze_evidence.py ../PhotoSamples \
  --auto-rotate --output /path/to/new-baseline
.venv/bin/python -B experiments/apple_native/coordinator_compare.py /path/to/new-baseline \
  --binary /path/to/bin/native-analyze --output /path/to/new-comparison
```

The comparison runs fresh native decoding, orientation, Vision, SIFT, measurements
and ranking; it checks all pair levels, applied rotations, focus/tier decisions,
reasons, ordering, UI summary ranks and original checksums. It uses the existing
measurement comparison's decision projection: raw continuous focus/detail evidence
is not required to equal Python's numerical reductions. Results of this fresh run
are separate from the historical frozen 151-image gate.
